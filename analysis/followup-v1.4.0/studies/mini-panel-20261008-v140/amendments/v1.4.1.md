# Operational amendment · v1.4.1

**Reported authorization:** on 2026-10-08 the user requested doubling, tripling or quadrupling resource utilization to accelerate the existing study.

**Verified measurements:** ten main containers were active, most used below 2 MiB at the sample, with a busy Python command using about 41 MiB. Each sidecar used approximately 15–17 MiB. This is a snapshot, not a peak bound. The VM has about 11.65 GiB usable RAM. A mock admission test verified that ten inherited workers plus thirty new admissions reach a global ceiling of forty; twenty further applicants wait. Actual trials must still establish provider throughput at this concurrency.

**Decision/inference:** increase the ceiling from ten to forty workers, using the same models, 120 planned primary trials, frozen tasks, inference settings, per-container CPU/memory limits and shared usage ledger. Do not add primary trials. Keep at least 3072 MiB VM MemAvailable before admitting work. Sample memory and the kernel termination counter every ten seconds. Trials observed during critical memory pressure below 1536 MiB are excluded irrespective of reward. A new kernel memory termination stops further dispatch; completed evidence is retained. Sampling cannot rule out every short resource spike.

**Handoff:** pause only the original dispatcher process with SIGSTOP. Its ten existing Harbor children continue unchanged, including active paid streams. The new supervisor accounts for those children in the global ceiling, collects their actual job results, and excludes their logical slots from the new queue. Interrupted children retain their evidence and can receive the original policy's fresh operational replacements; no graded failure is retried. After all work is collected, the old paused service is removed. Source hashes, inherited attempt IDs and child PIDs are in v1.4.1.json. No inference request was deliberately interrupted by the handoff.

**Persistence and provenance:** the new system service runs as matrix and survives client disconnection. It reuses the original three successful smokes and original harness source without editing them. Code and plan revisions are committed before new dispatch; the original freeze is unchanged. Existing milestone commits continue, and the final summary includes inherited results. Low local CPU usage remains possible because inference runs on Fireworks; quadrupling concurrency does not promise quadrupling throughput.
